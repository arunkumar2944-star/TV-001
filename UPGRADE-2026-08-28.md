# Trichy Vision identity/tenancy correction - 2026-08-28

This revision establishes the identity model required before client registration.

## Canonical identity model

- `client_users.user_id` is the canonical user key.
- `PLATFORM_ADMIN` is global and has `client_id = NULL`.
- `CLIENT_ADMIN`, `CONTENT_CREATOR`, `EDITOR`, and `APPROVER` are client-scoped.
- Existing newsroom code receives a temporary `id` alias from `userService` for compatibility while the rest of the application is migrated incrementally.

## Security corrections

- The unauthenticated `POST /api/platform-admins` endpoint is now a one-time bootstrap only. It returns a conflict after any platform administrator exists.
- JWT `sub` uses `user_id` and contains the current `client_id` as context.
- Authentication still reloads the user from PostgreSQL on every request, so database role, client, and activation state remain authoritative.
- The real `.env` file and `.git` history are intentionally excluded from the distributed corrected ZIP.

## Route correction

The platform-admin bootstrap is now isolated from `/api/users`; mounting the full user-management router at `/api` previously exposed unintended route aliases.

## Next development checkpoint

The next module is client registration and client-scoped administration. Do not connect social accounts to a global platform admin until a client has been selected.
